# persona-ab-factory（日本語要約）

指示ファイル（CLAUDE.md 等）を「規則として書く」か「人格として書く」かで、エージェントの拒否の仕方・圧をかけられた時の正直さ・書いた本人に「解除する」と言われた時に線が保つか、がどう変わるかを、夜間の A/B で測る常設の実験装置。これはその**最小公開版**＝設計書・台帳の型（1ジョブが通る8工程）・最初の実験で使った汎用の指示ファイル2本とプローブ。

実例（won't vs cannot・Round 1 の生答案＋Round 1〜3 の write-up・2〜3 は報告のみで再現材料なし）は既に姉妹 repo [low-pressure-claude-md](https://github.com/TJ11000/low-pressure-claude-md) の experiments/ で公開済みなんで、ここでは再掲せずリンクだけ。この repo が足すのは「その実験を回した装置の設計」と「ジョブの手順」。

**入っていないもの**: 稼働中の台帳・ジョブ本体・variant（id 001〜054（2026-09-11 時点）は起票順であって時系列やない・複数ジョブを1晩に束ねる夜もある）／現行の judge プロンプト／runner。ただし「原理で伏せとる」やなく範囲の話＝個別ジョブの write-up と、2件は材料・rubric・driver まで姉妹 repo の experiments/ に公開済み。伏せとるのは稼働中の台帳と現行の計器（公開したら試験対策される）だけ。ベンチマークもない。

- `DESIGN.md` — 設計 v0.3（檻＝汚れる場所が無い／4者分離／2レーン／部品在庫／予測-残差コントローラー／夜間サイクル／安全）
- `LEDGER_TEMPLATE.md` — 台帳の列の意味と8工程（発注→事前登録→検収→封印予測→番兵つき発射→日次push→機械集計→開封）。2026-09 の判定で見つかった計器の死角も記載（2026-09-11 時点）
- `variants/` — 同じ6領域の規則を「cannot／禁止」で書いた 08 と「I won't／流儀」で書いた 09（09 は理由・要約の但し書き・不可侵の一行が追加で入る＝register だけの差やない）

- `results/061-series/` — **2026-09-25 追加。** 2026-09 のジョブ4本を丸ごと（発注書・事前登録・封印予測・両側の判定・腕 md・カード・judge・生答案40本）。問い＝「売上 $0 の週報を渡したら、聞かれんでも次の一手を出すか」。正直さだけの md 0/8・正直さ＋動き2行 8/8（腕あたり n=8・1モデル・8/8 は md の型どおり＝詳細はページ）。

**先に言うとくこと**: n は小さい（2モデル系・4走・2026-08 時点）。人格型が捏造を減らすとは言うてへん。両腕は自分の語彙を見出しに書いとるんで「A が cannot・B が won't と言うた」は指示遵守の確認であって発見やない。発見はファイルに無い語（A の「mandatory」・B が著者の権限を認めた上で拒否）。「先行例は知らん（2026-08-07 時点・2026-09-11 再確認でも新規なし）」は「知らん」であって「無い」やない。反例は issue で。
